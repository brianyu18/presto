Combined approach · skill no. 04

Three skills. One workflow. No conflict.

Impeccable owns the project lifecycle. The taste skill owns the page-level brief. Emil owns the component-level craft. Stacked, they cover every altitude — and the conflicts that look real on paper are easily resolved by ownership.

Conflict resolution.

Three conflicts look real on paper. All three resolve by ownership — the skill at the relevant altitude wins.

ConflictImpeccable saysTaste saysEmil saysWinner
Bounce in easing No bounce. Exponential ease-out. Silent on bounce shape. Subtle 0.1–0.3 OK for playful / drag UI. impeccable · for UI; emil · for drag-to-dismiss only
Eyebrows Banned as scaffolding when on every section. Max 1 per 3 sections, mechanical count. Silent. taste · its count is the operational rule
Default sans font Doesn't prescribe. Discourages Inter. Reach for Geist / Outfit / Satoshi first. Silent on family. taste · brief-aware
Animation altitude "Motion must be intentional." Picks the pattern (sticky stack, horizontal pan). Picks the curve, duration, origin. taste · pattern; emil · values
Beige / cream backgrounds "Saturated AI default of 2026." Banned. Premium-consumer beige+brass family banned. Silent. both agree · use the rotation table
Marketing copy No marketing buzzwords. No em dashes. Copy self-audit. Cut AI cute-but-wrong phrases. Silent. both agree · enforce together

What each skill owns.

The clean partition. When you're stuck, ask which row your question sits in — and only consult that skill's reference.

Impeccable

Project & register

  • PRODUCT.md / DESIGN.md context loading
  • Brand vs. product register split
  • Color strategy (restrained · committed · full · drenched)
  • OKLCH palette + tinted neutrals
  • Cross-register absolute bans
  • Sub-commands: critique, audit, polish, harden, document, extract, ship
  • AI slop test (first + second order)

Taste skill

Page & brief

  • Design Read (one-line)
  • VARIANCE / MOTION / DENSITY dials
  • Brief → real design system map
  • Anti-default discipline (Inter, AI-purple, beige+brass)
  • Hero discipline (max 4 elements, fits viewport)
  • Eyebrow / section / zigzag / marquee limits
  • Pre-Flight checklist (mechanical)

Emil

Component & motion

  • Animation Decision Framework
  • Custom easing curves (3 named)
  • Duration ceiling (≤300ms UI)
  • Spring physics for drag / alive elements
  • scale(0.97) on every :active
  • Never scale(0); always 0.95 + opacity
  • Popover transform-origin
  • clip-path tricks (hold-to-delete, image reveal)
  • Review-as-markdown-table format

Utility skill alongside the three: imagen-direction — anti-slop prompt patterns for nanogen (avoid "epic / cinematic / dreamy / vibrant"; reach for "editorial / off-center / harsh window light / scanned slide film / brand palette dominant"). Sits at the presto-utilities altitude with impeccable, taste, and emil.

Why one plugin instead of three

Shared shared/ means easing curves and palette tools aren't duplicated. The Design Read is written once and consumed by all three.

Why three skills not one

Each skill keeps its own description and trigger context. Claude picks the right one based on the user's altitude — the SKILL.md descriptions stay specific and discoverable.

Adoption path.

Three reasonable starting points, depending on what's already installed.

Starting fresh

Install presto directly.

The plugin pulls all three skills as siblings. Run /design-read on first invocation; the rest follows from the read.

/plugin install presto

Already on impeccable

Layer in taste + emil only.

The plugin detects an existing impeccable/ install and skips re-adding it. Memory and shared/ still come along.

/plugin install presto --partial

Picking and choosing

Use the skills individually.

Each skill works alone. The cost is repeated setup and no shared Design Read between sessions.

One slash command. Seven phases (plus a conditional cold-start). Six break-out points. Memory that survives the session.

When the MCP fails or quota is hit

Graceful degradation: empty mood_board, empty visual_direction_summary, the rest of houdini proceeds with text-only direction. The intentional version of this fallback is the --nogen flag — covered next.

Posture matrix.

Every mode pairs with a --nogen variant. Same path, MOOD skipped, no Gemini image-gen draw. Use it when quota is hit, when iterating fast, or for text-only exploration.

Cost model
  • /magic phases 1–7 run against the Claude subscription, not Gemini.
  • MoodBoard runs against the Gemini image-gen quota — 3 calls per houdini run.
  • /imagen and /imagen-edit also draw from the image-gen quota.
When quota is hit
  • --nogen is the graceful degradation path. Append it to any of the modes above.
  • If the MCP fails mid-run, houdini auto-falls-back to empty mood and text-only direction.

When to use --surprise
  • You trust the wildcard angle and would rather react to a finished design than pick from drafts.
  • You want maximum velocity from blank brief to AUDIT in a single command.
When NOT to use
  • When the project is high-stakes and you want oversight per phase: use --guided.
  • When you want the three-option spread to evaluate visually: use bare /houdini (guided mode).

The combined approach, in one sentence.

Read the room with taste, load context and pick the register with impeccable, build with both, polish every animation with emil, and audit against all three before ship — packaged as presto so the Design Read and dials persist across sessions.
