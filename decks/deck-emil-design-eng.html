The animation decision framework.

Before writing any animation code, walk these four questions in order. Every animation must answer every question.

1

Should this animate at all?

How often will users see it? Keyboard-initiated actions (100+/day) never animate. Raycast has no open/close animation — that's the optimal experience.

2

What is the purpose?

Spatial consistency · state indication · explanation · feedback · preventing jarring changes. "Looks cool" is not a purpose when the user will see it daily.

3

What easing should it use?

Entering / exiting → ease-out. Moving on screen → ease-in-out. Hover → ease. Constant motion → linear. Never ease-in on UI.

4

How fast should it be?

Under 300ms is the rule for UI. 180ms dropdown feels more responsive than 400ms. Easing amplifies this — ease-out at 200ms feels faster than ease-in at 200ms.

Custom easing. Built-in curves are too weak.

The CSS defaults lack the punch that makes animations feel intentional. Use stronger custom variants. The shaped curves below are the same ones Emil ships.

ease-out · for UI interactions cubic-bezier(0.23, 1, 0.32, 1)

Hover this card to watch the puck. Starts fast, settles smoothly. Feels responsive.

ease-in-out · for on-screen movement cubic-bezier(0.77, 0, 0.175, 1)

How fast.

UI animations stay under 300ms. The element decides the range. Anything longer reads as sluggish — even when the timing is "technically" within reason.

A fast-spinning spinner makes loading feel faster, identical load time. Perceived performance is a real lever.

Spring physics for things that should feel alive.

Springs simulate real-world physics. They don't have fixed durations — they settle. Use them for drag with momentum, elements that should feel "alive," and gestures users might change mid-motion.

Move your cursor across the stage.

Instant tying to mouse position lacks motion. Spring interpolation feels natural and is interruptible mid-flight.

Buttons must feel responsive.

Add transform: scale(0.97) on :active. Subtle, but instant feedback makes the UI feel like it's listening. Try pressing the one below.

Why it compounds

Whether the user notices individually doesn't matter. In the aggregate, unseen details become visible.

Pair with filter: blur(2px) during state transitions when crossfades feel off — blur masks the visual overlap of two states.

Asymmetric timing: slow on press (deliberate), fast on release (responsive). Press 2s linear, release 200ms ease-out.

Never animate from scale(0).

Nothing in the real world appears from nothing. Start at scale(0.95) with opacity: 0. Even barely-visible initial scale makes the entrance feel natural — like a deflated balloon has shape before it's filled.

Avoid

scale(0) → scale(1)

Balloon

Pops out of nothing. The eye reads it as appearing, not entering.

Reach for

scale(0.95) + opacity 0 → scale(1) + opacity 1

Balloon

Has shape before it arrives. Reads as materializing, not appearing.

Popovers scale from their trigger.

The default transform-origin: center is wrong for almost every popover. They should appear to grow from the thing that opened them. Modals are the exception — they stay centered.

From trigger · correct
Anchored to the trigger. Scales from the top edge.

transform-origin: 50% 0

From center · wrong
Floats out of the middle of itself. Disconnected.

transform-origin: 50% 100%

Asymmetric timing in two seconds

The press uses linear timing over a long duration — the user is deciding, the interface acknowledges. The release uses ease-out over 250ms — the system is responding, fast as possible.

Same pattern: slow where the user is deciding, fast where the system is responding. Drag-to-dismiss, hold-to-confirm, expand-to-fullscreen all follow it.

The Sonner principles.

Six lessons from building a component shipped 13M+ times a week. They apply to any UI component, not just toasts.

Developer experience is key

No hooks, no context, no setup. Insert once, call from anywhere. Less friction → more adoption.

Good defaults beat options

Most users never customize. The default easing, timing, and visual must be excellent.

Naming creates identity

"Sonner" (French: to ring) is more memorable than "react-toast." Sacrifice discoverability when warranted.

Handle edge cases invisibly

Pause timers when the tab is hidden. Fill gaps between stacked toasts. Users never notice — exactly right.

Transitions, not keyframes

Toasts add rapidly. Keyframes restart from zero on interruption. Transitions retarget smoothly.

Cohesion matters

Easing and duration fit the vibe. Animation style matches the name. Match motion to mood.
